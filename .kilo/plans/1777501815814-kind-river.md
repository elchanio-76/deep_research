# Plan: Add MS Word (DOCX) Export Format

## Overview

Add support for exporting research reports as MS Word documents (.docx), following the existing architecture pattern for Markdown and PDF exports.

## Architecture Summary (Current)

The export pipeline is designed as a deterministic, no-LLM document generation system:

```
src/export/
├── models.py        # ExportFormat enum, DocumentParts dataclass, ExportResult
├── service.py       # Orchestrates DB fetch → build DocumentParts → delegate to renderer
├── router.py        # FastAPI endpoints for each format
├── errors.py        # ExportError hierarchy
└── renderers/
    ├── markdown.py  # Pure render(parts) → str
    └── pdf.py       # render(parts) → bytes (via markdown → HTML → weasyprint)
```

Key patterns:
- Each renderer exports a `render(parts: DocumentParts) -> str | bytes` function
- PDF renderer reuses Markdown output, then converts to HTML → PDF via weasyprint
- Service layer abstracts format selection; router just calls `export(session_id, fmt, pool)`
- No imports from `src/agents/` or `src/core/research_manager` in the export package

## Markdown Parsing Approach (Confirmed)

**Native markdown parsing** - Parse markdown directly with regex and create DOCX elements. No extra dependencies needed.

Supported markdown elements:
- Headings (`#`, `##`, `###`, `####`, `#####`, `######`)
- Bold (`**text**` or `__text__`)
- Italic (`*text*` or `_text_`)
- Code blocks (fenced with ` ``` `)
- Inline code (`` `code` ``)
- Bullet lists (`- item` or `* item`)
- Numbered lists (`1. item`)
- Links (`[text](url)` - rendered as underlined text with URL in parentheses)
- Paragraphs (separated by blank lines)
